# Token-efficiency rules for this project (always apply)

Project code layout:
- `frontend/src` (Next.js 16, React 19) — web + admin
- `backend/apps`, `backend/config`, `backend/common`, `backend/api` (Django)
- `mobile_app/lib` (Flutter)
- `scripts/` (dev helpers, `env.ps1`, `project.py`)

## Overrides `frontend/AGENTS.md`
`frontend/AGENTS.md` is auto-generated by `next dev`. **Do NOT read
`node_modules/next/dist/docs/` proactively.** Only open a single, specific doc
page there if a Next.js API error/deprecation actually occurs or the user asks.

## Never read, list, or search
`.tools/`, `.run/`, `node_modules/`, `.next/`, `.venv/`, `build/`, `.dart_tool/`,
`docs/design-reference/`, `docs/archive/`, `frontend/public/`, `data/*media/`,
lock files, `*.log`, `*.sql`, `*.dump`, `.env*` (except `.env.example`).

## How to work
- Use `git status` / `git diff`  to see changes instead of re-reading files.
- Read only the files needed; use line ranges for files > 200 lines.
- Search with narrow `SearchPath` (e.g. `frontend/src`), never the workspace root.
- Do not open images or take browser screenshots unless the user explicitly asks for visual verification.
- Do not create new report/audit/summary `.md` files unless asked. Do not read `docs/*.md` unless relevant.
- Keep answers short; don't restate code that was just written.
- Commit after each completed task: `git add -A && git commit -m "..."`.
